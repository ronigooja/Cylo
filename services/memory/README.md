# Cylo memory worker

The worker runs outside the Go control server. Go remains authoritative for claims, proposals, source availability, and tombstones. The worker claims fenced jobs over the authenticated runner API, validates each job immediately before a derived-store effect, and completes or safely retries it. Extracted facts are submitted through the runner proposal route and remain pending user review.

The worker uses Mem0 2.2.1 with Qdrant for controlled source extraction and scoped recall. A separate Qdrant collection stores only vectors and revision/source metadata for current Go claims; it omits claim text. Both stores call the worker's same hash-verified FastEmbed 0.9.0 instance, using its ONNX Runtime CPU backend and the multilingual model `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (384 dimensions, cosine distance) from pinned ONNX snapshot `Qdrant/paraphrase-multilingual-MiniLM-L12-v2-onnx-Q@faf4aa4225822f3bc6376869cb1164e8e3feedd0`. Startup verifies model artifact hashes before processing jobs. The collection name includes the codec version so a future embedding change requires a distinct collection and rebuild. Qdrant is disposable and can be rebuilt from Go authority.

Mem0's SQLite history database is persistent worker state, separate from Go's authoritative memory ledger. It stores scoped memory-ID ownership so a tombstone can remove only that claim's history and messages even when Mem0 inference already deleted one of its vectors or the worker restarted. Keep `CYLO_MEM0_HISTORY_DB` on a private persistent volume; the default Compose service mounts it under `/var/lib/cylo/memory` with restrictive file permissions. Unknown history IDs without an ownership record are retained rather than purged broadly.

Configure the required `CYLO_*` variables in the deployment environment. The LLM provider may be a local Ollama endpoint or an OpenAI-compatible endpoint. Set `CYLO_MEM0_LLM_API_KEY` through the deployment's secret reference; do not place credentials in repository files. Runner policy must allow the exact `memory:jobs:claim` and `memory:jobs:complete` scopes for its workspace allowlist, plus `memory:propose` for candidate submission.

Run from the repository root with `python -m services.memory.worker`. `docker-compose.yml` supplies an isolated disposable Qdrant service and worker container. The implementation has explicit adapters for Qdrant index/deletion and Mem0 deletion. Other cleanup targets fail with a permanent `adapter_missing` error and are never acknowledged as successful.

The cross-language acceptance test is opt-in. Set `CYLO_MEMORY_E2E=1`, `CYLO_MEMORY_E2E_LLM_BASE_URL`, `CYLO_MEMORY_E2E_LLM_MODEL`, and `CYLO_MEMORY_E2E_LLM_API_KEY` (from the existing deployment's secret reference), then run `go test ./tests/integration -run '^TestMemoryWorkerGoPythonMem0QdrantEndToEnd$' -count=1`. It starts and removes a pinned local Qdrant container, uses synthetic source text and a temporary Go authority database, and does not modify the provider deployment.
