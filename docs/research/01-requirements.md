# Cylo 新版需求追踪、验收与交付边界

调研日期：2026-10-21。本文完整阅读并以 [新版完整需求](../../Cylo-完整产品需求说明书.md) 为唯一产品需求基线；[旧需求与架构讨论稿](../../codex-super-agent-requirements-and-architecture.md) 仅作历史对照。当前基线已按用户最新决定取消官方 Codex 桌面 App 支持；保留基础 CLI、macOS 客户端/浏览器及跨环境迁移，服务端平台以以下最新范围说明为准，§5.2编号保留。最新优先级另将人工同 thread 无缝接管、双向原生交接与复杂控制权协议改为可选增强；基础 CLI 执行、停止查看与持久恢复仍必须。以下组件、阶段、数据结构和数值指标是实施建议，不是对原文的改写，也不是已经实现或实测的能力。

**最新平台范围（优先于下表旧双平台表述）：** 首期仅保证 Linux 服务端与执行宿主部署及其基础 CLI 执行、停止查看和恢复；表中 Mac/Linux 后台、双平台 CLI 与 Mac→Linux 执行恢复验收，首期均按 Linux 主机运行/迁移验收。macOS 客户端/浏览器、用户自行使用 CLI、跨设备项目访问及备份导出保留；macOS 上运行 Cylo/AO/Worker 后台服务后续按需评估，不纳入首期验收。稳定需求 ID 保留。

## 1. 结论与证据边界

Cylo 是持久运行的开放式执行系统。客户端、任务权威状态、Agent、长期服务与长期记忆必须分开；不能把它缩成聊天界面或终端 Agent 编排。所有22章的必需范围共同定义最终产品，场景A—E是跨组件验收链路；任一阶段子集交付均不代表最终产品完成。

第五章需区分基础 CLI 执行/停止查看/保存会话恢复，与可选的人工会话发现、反向识别、运行中输入交接。基础恢复不通过会阻断对应自动执行闭环；人工无缝交接缺失不再阻断选型或必需范围验收。无论是否实现增强，都必须防止未经协调的双写，并如实标注支持边界；导出摘要或重建聊天不能冒充原生会话恢复。

本文只基于仓库两份需求文档分析，不独立宣称候选项目已支持某能力。候选代码、官方协议和语音平台的外部事实分别由同目录编排/语音/架构研究提供；本文列出的是需要取得的证据。仓库静态阅读、接口文档说明与真实端到端通过必须分别记录。

## 3. 矩阵读法与责任边界

稳定ID为 `CY-章号-条目号`，优先对应原小节；无小节章节拆成明确条目。ID不随未来实现、文件行号或阶段改变。场景用 `CY-19-A` 至 `CY-19-E`。每行包含原始出处、要求、责任组件、依赖/风险、最早交付阶段和可验证验收；逗号分隔的要点均属于该行覆盖范围。

组件：**端**=macOS/iPhone/iPad交互客户端；**核**=请求/项目/任务/事件/权威状态控制面；**适**=Codex及其他Agent/模型适配层；**协**=Super/Worker规划执行；**服**=普通程序/服务注册与运行管理；**忆**=历史、来源、记忆整理和检索；**安**=身份/授权/隔离/审计；**运**=运行监督、健康、恢复、备份与部署。责任组件是主责，不意味着其他组件不参加。

阶段：**P0**=阻断性POC与协议/状态契约；**P1**=可信任务与跨设备开发闭环；**P2**=长期服务、自主扩展与可靠记忆闭环；**P3**=完整跨平台/替换/迁移/质量验收。阶段为最早可交付完整该条的目标；POC在P0先行，即便功能交付在后续。**直**=可直接按成熟工程方式实施，但仍须验收；**试**=必须先POC，不能仅凭方案承诺。POC不是生产就绪证明。
